# План и итоги рефакторинга

Документ фиксирует цель, границы и выполненные этапы приведения CaseLab EDM к
предсказуемой, безопасной и поддерживаемой архитектуре с отдельными
identity- и бизнес-сервисами.

## 1. Цель

- Убрать из репозитория секреты и сделать конфигурацию окружений явной.
- Закрыть критические дефекты авторизации и целостности данных.
- Разделить ответственность слоёв: контроллер → сервис → репозиторий.
- Вынести identity в отдельный запускаемый `security-service`.
- Оставить в `platform-spring-boot-starter` только переиспользуемые технические
  интеграции.
- Организовать backend по bounded contexts DDD.
- Сохранить публичные URL бизнес-API.
- Сделать локальный запуск, тесты и автоматический деплой воспроизводимыми.
- Достичь покрытия не ниже 90% строк в каждом модуле.
- Актуализировать документацию на русском языке.

## 2. Границы работ

В scope: `pom.xml`, `platform-spring-boot-starter/**`,
`security-service/**`, `backend/**`, `docker/**`, `.github/workflows/**`,
`README.md`, `docs/**`.

Вне scope: изменение бизнес-требований, переписывание UI, миграции данных,
которые не требуются для исправления найденных дефектов.

## 4. Риски и меры

1. **Секреты уже в истории Git.** Ротация JWT/БД/почты/MinIO обязательна;
   чистка истории не заменяет ротацию. См. `SECURITY.md`.
2. **Разделение баз.** Backend больше не содержит identity-таблиц. Миграция 1.2
   переименовывает legacy-колонки и удаляет FK на `users`; перенос пользователей
   в отдельную базу `security` остаётся ручным, а fresh-развёртывание получает
   две пустые базы и независимые миграции.
3. **Деплой зависит от `.env` на сервере.** Мера: документирован one-time setup,
   `.env.example` и fail-fast в compose.
4. **Недоступность MinIO/Elasticsearch/security-service.** Мера: флаги
   инициализации, контролируемые ошибки `UserDirectory`, health endpoints.
5. **Дублирование JWT-секрета.** Мера: один `JWT_SECRET` в secrets, ротация
   обоих сервисов одновременно.

## 5. Проверка

```bash
./mvnw -ntp clean verify
```

Ожидаемо: сборка успешна, все unit/integration-тесты зелёные, покрытие каждого
модуля ≥ 90%, context-тесты не требуют Docker.

Дополнительно:

```bash
docker compose --env-file .env -f docker/docker-compose-server.yaml config
```

должен валидировать compose при заданном `.env`.
