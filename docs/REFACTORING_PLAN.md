# Техническое задание: рефакторинг backend CaseLab EDM

Документ описывает цель, границы и последовательность работ по приведению backend к
предсказуемой, безопасной и поддерживаемой архитектуре. Задачи специально разбиты на
небольшие шаги, каждый из которых можно проверить и замёржить отдельно.

## 1. Цель

- Убрать из репозитория секреты и сделать конфигурацию окружений явной.
- Закрыть критические дефекты авторизации и целостности данных.
- Разделить ответственность слоёв: контроллер → сервис → репозиторий.
- Сделать локальный запуск, тесты и автоматический деплой воспроизводимыми.
- Достичь покрытия не ниже 90% строк с проверкой ключевых сценариев подписания.
- Актуализировать документацию на русском языке.

## 2. Границы работ

В scope: `backend/**`, `docker/**`, `.github/workflows/**`, `README.md`, `docs/**`.

Вне scope: изменение бизнес-требований, переписывание UI, миграции данных, которые
не требуются для исправления найденных дефектов.

## 4. Риски и меры

1. **Секреты уже в истории Git.** Ротация JWT/почты/БД обязательна; чистка истории
   не заменяет ротацию. См. `SECURITY.md`.
2. **Изменение схемы не требуется**, но переименование Java-поля затрагивает JPQL.
   Мера: все запросы и тесты обновлены, колонка БД оставлена `state`.
3. **Деплой зависит от `.env` на сервере.** Мера: документирован one-time setup и
   добавлен `.env.example`; compose падает с понятной ошибкой при отсутствии переменной.
4. **MinIO/Elasticsearch могут быть недоступны локально.** Мера: флаги инициализации
   и нефатальный старт.

## 5. Проверка

```bash
cd backend
./mvnw -ntp clean verify
```

Ожидаемо: сборка успешна, все unit/integration-тесты зелёные, context-тест не требует
Docker. Дополнительно:

```bash
docker compose -f docker/docker-compose-server.yaml config
```

должен валидировать compose при заданном `.env`.
